# 0001 · 源库全程只读，分类状态只落独立的侧状态库

- 状态：已接受
- 日期：2026-08-24
- 背景：Finder 要同时消费 Analyzer 的 SQLite 与自身历史库。若顺手把分类状态（跳过 / 归档 / 视图 / 名单）写回源库，一旦源库被外部重新导入或覆盖，状态即丢；同时会与 Analyzer 自身的写库形成双写冲突。Phase 1「接 Analyzer 全量」需要一条不可动摇的边界。
- 决策：所有源库一律以 `file:...?mode=ro` 只读打开，绝不 INSERT / UPDATE / DELETE；分类与整理状态只写 `data/canonical_state.db`，与源库**物理隔离**。
- 理由：源库是上游 Analyzer 的产物、随时可能被重建；只读使"在真实全量上跑验证"零风险；侧库可独立备份与迁移。放弃"就近写回源库"，是因为那会把状态的生命周期与上游绑死，且一旦源库结构变动就整体失效。
- 影响：`src/store.py` 全部读路径必须走 `mode=ro`；新增任何"整理类"能力都落侧库；`src/collector.py` 是唯一写本地 Finder 库的例外（写的是自有库，**不是** Analyzer 源库）。副作用是正面的：`kid = (bvid, view_at)` 因此成为跨源、跨模式的稳定状态键 —— **切换数据源不需要迁移状态**（见 [0005](file:///d:/Programs/Share/BilibiliHistoryFinder/doc/adr/0005-保留mode-local分支.md)）。
