# 0003 · R3 的 `span_peak_days` 由「同步成功后写回」维护，在此之前 R3 恒不触发

- 状态：已接受
- 日期：2026-09-26
- 背景：「连接即模式」阶段 1 落地时，冒烟实测发现 **R3 的原判据「缺口 = 主源条数 − 本地条数」是错的**：`analyzer_days=2452` vs `local_days=134`，R3 会立刻命中 `full` —— 但这是 B站接口"只保留近三个月"造成的**结构性差异**，不是缺口，会导致每 7 天白跑一次全量（而全量同样补不回 2020–2024）。判据改为「本地跨度 vs 历史峰值」后，暴露出新问题：**没有任何地方写入这个峰值**（阶段 1 全程只读）。
- 决策：`span_peak_days` 由「每次成功同步后把本地跨度峰值写回 `meta`」维护，该写回步骤归入后续阶段（D 项 / 阶段 2）；**在此之前 R3 恒为 `None` → 保守不触发**。
- 理由：两者相权，宁可"该触发时不触发（少跑一次全量）"，也不要"把结构差异当成缺口（定期白跑全量）"。把写回挪到后续阶段，是为了让阶段 1 保持**零持久化副作用、可随时停**。
- 影响：R3 在写回落地前是一条**休眠规则，不是遗漏** —— 文档与代码注释都须如此标注，避免后人误判为 bug 去"顺手修"。落地时须同时补单测覆盖"峰值已写 / 未写"两种输入；`meta` 增加一个字段。相关待定项编号为 **O12**（见 `方案.md`）。
