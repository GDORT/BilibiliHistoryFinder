## 4. ADR 规范

文件名：`doc/adr/NNNN-短标题.md`，模板固定六段。

```
# NNNN · <一句话决策>
- 状态：已接受 | 已取代（被 NNNN）
- 日期：YYYY-MM-DD
- 背景：为什么必须做这个决定（2–3 句）
- 决策：一句话
- 理由：为什么不选另一条路
- 影响：谁要跟着改
```

**规则**：一条决策一页，**永不修改**。被推翻时在新 ADR 里写 `状态：已取代（被 NNNN）` 并回指旧页，旧页只加一行状态。

## 5. 四条铁律

1. **事实只写一次**：能力数、端口 `8765`、`ANALYZER_DB` 路径、`PAGE=60`、各库条数等，只在 `现状.md` 定义；其余文档（**含 `doc/` 之外的仓库根 `README.md` 与 `dev/README.md`**）一律**链接引用**，不复制。每多抄一份，未来就多一个需要同步的失败点。
2. **文档头三行元信息**（见 §3）。
3. **轮次记录剪切而非积累**：`待办.md` 只留未完成；做完的**剪**到 `log/`。
4. **闭环即冻结；阶段完成才归档**：审查 / 评估类文档一旦所有条目都有处置结论 → **冻结并留在 `log/`**（过程快照）；新发现**开新报告**，不追加章节。
   `archive/` 的触发条件是**另一个**：只在**一个阶段整体完成、其方案稿被取代**时，接收那一批被取代的方案稿。
   > 因此 `adr/`（决策）＋ `log/`（过程）是一组持续记录，`archive/` 是阶段性的终点仓 —— **两者职责不冲突**。
   > （2026-10-01 文档重整把三轴方案原稿等搬入 `archive/`，属「文档体系这一阶段完成」的一次性搬迁，不是新规则。）

补充约定：`F-H1` / `C-H1` 这类编号**只属于其所在的那一份快照**；跨文档引用时必须写全「来源文档 §编号」。
