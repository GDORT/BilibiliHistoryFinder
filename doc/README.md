## 两条线

本仓库有两个互相独立的入口，各有各的文档：

| | **入口 A · 服务端** | **入口 B · 浏览器脚本** |
| --- | --- | --- |
| 代码 | `src/` `data/` `start.bat` | `../src/userscript/` ＋ 根产物 `bili_history.user.js` |
| 文档 | 本目录的三份 ＋ 油猴两份 | [**油猴脚本.md**](油猴脚本.md)（真相源）· [**油猴脚本接口事实.md**](油猴脚本接口事实.md) · [**发布页**](油猴脚本发布页.md)（贴给用户） |
| 要凭证 | 依赖 Analyzer | 不需要 |
| 数据在哪 | 本机 SQLite | 浏览器 IndexedDB |

两者**不共享数据**，唯一往来是手工导出/导入 JSON。

## 约定

1. **事实只写一次** —— 端口 / 路径 / 端点 / 常量只在 `现状.md` 定义，其余文档一律链接引用，不复制。
2. **不新增第八份文档** —— 要写新内容，先判断该进上面哪一份。
3. **油猴线的代码在 `src/userscript/`**（与 `src/` 共库），但**运行、数据、验证全独立** ⇒ 不与入口 A 混放。
4. **技术文档 ≠ 用户文档** —— `油猴脚本.md` 面向维护（含验证命令、源码结构），`油猴脚本发布页.md` 面向使用者（不含任何内部细节）。发布只贴后者。
5. **`历史留档/` 是纯备份** —— 冻结不动，活文档不引用它。
