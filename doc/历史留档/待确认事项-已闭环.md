## C2 · 确认 gitcode 仓库是 public 还是 private

| | |
| --- | --- |
| **类型** | 拍板（1 分钟） |
| **影响** | 决定是否要**彻底重写 git 历史**（force push，不可逆） |
| **状态** | ⏳ 待你确认 |

### 做什么

打开 gitcode 仓库页面（`https://gitcode.com/basic_597/BilibiliHistoryFinder`），确认可见性是 public 还是 private，告诉我就行。

### 为什么

你之前问过「历史里还能翻到已归档文档，能不能彻底删掉」。
我扫描过全部历史（103 个文件），结论是：

| 检查项 | 结果 |
| --- | --- |
| `config.json`（**真实 SESSDATA**）曾否入库 | ✅ **从未** |
| `data/`（**真实历史数据库**）曾否入库 | ✅ **从未** |
| 历史 `doc/` 66 个文件含真实凭据值 | ✅ **零**（`SESSDATA` 只是讨论用的词，不是值） |
| 817MB 的 `e2e` 依赖曾否入库 | ✅ **从未** |

⇒ 历史里**全是普通文档快照，无敏感内容**。

- **private** → 建议**不动**。force push 的代价（改写全部 hash、他人 clone 冲突、不可逆）远大于收益。
- **public 且你介意** → 才值得考虑 `git filter-repo` + force push（命令已给过，执行前必须全仓备份）。

### 怎么判断

回答一个词：public / private。

### 不做的后果

不影响任何功能；只是这个决定一直悬着。

## C3 · 确认 `dev/` 与 `doc/` 移出版本控制是否可接受

| | |
| --- | --- |
| **类型** | 拍板 |
| **影响** | clone 仓库后**没有文档与测试** |
| **状态** | ⏳ 待你确认（我已按「可接受」处理了一个连带问题） |

### 现状

你在 10-09 把 `dev/`、`doc/`、`data/`、`output/` 写入 `.gitignore` 并 `git rm --cached`。
现在仓库**只跟踪 13 个文件**（全是本体代码）。

⇒ 别人（或你在另一台机器）`clone` 之后：**没有文档、没有测试脚本**，只有能跑的本体。

### 我已处理的连带问题

根 `README.md` 原本有 **24 处 `doc/` 引用**，移出后全是死链。
重写时我已**清掉全部引用并改为自足**（端口 / 路径 / 规则字段 / 测试项数直接写进正文）。

### 要不要调整

| 选项 | 做法 | 适用 |
| --- | --- | --- |
| **A. 维持现状**（我已按这个处理） | 仓库只放本体代码 | 你只在本地用、不需要 clone 后有文档 |
| **B. 把文档入口加回仓库** | `.gitignore` 加 `!doc/README.md` 例外，再 `git add -f` | 希望 clone 后能看到文档索引 |
| **C. 把 `dev/` 也加回** | 去掉 `dev/` 忽略 | 希望 clone 后能跑回归测试 |

### 不做的后果

不影响任何功能 —— 只是 clone 后仓库会比较"裸"。
