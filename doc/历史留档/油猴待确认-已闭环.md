## C5 · 「主动补请求」——**已按方案决定：被动旁听，不做**

| | |
| --- | --- |
| **类型** | 已决定（方案既定，非新增功能，无需拍板） |
| **结论** | **维持被动旁听**：不实现主动翻页 GET；覆盖度仅限"用户实际浏览过的分类" |
| **状态** | ✅ 已落定（`runtime.js` 注释已写明；非待决策项） |

### 追加确认（2026-10-09 用户）

> "他不需要去对数据的来源进行负责，他只需要拉取就可以了。"

⇒ **「本地独有记录分组 / 服务端已删」标注 = 不做**（方案 §M6 该项作废，属超出职责范围）。
导出维持 **本地存储为主 ＋ JSON 下载为辅**（JSON 只用于交给 Finder／备份，非唯一数据源）。

### 依据

旁听只能拿到用户实际浏览过的分类（SCHEMA 限制 1/2/3）。主动翻页 GET 虽不违反"不回写"红线，
但**会消耗风控额度**——方案把它定为"默认关闭、日后单独评估"，本版**不实现**，也不作为新需求提出。
长期全量留存仍靠「定期导出 JSON → 回灌 Finder」。

### 不做的后果

不影响任何已验证功能；覆盖度受"浏览过才抓"限制（与方案预期一致）。
