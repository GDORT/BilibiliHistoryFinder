## 二、流程总览（7 步，按依赖排序）

```
M0 骨架与地基        ← 能跑起来、能抓到数据
 ↓
M1 双存储（IndexedDB） ← 数据存得下、不丢字段
 ↓
M2 引擎 JS 移植       ← ⭐ 最重的一步，含对拍验证
 ↓
M3 引擎对拍验收       ← 与 Python 引擎逐条对照（本流程的核心防线）
 ↓
M4 overlay 注入       ← 在 B站原页上"看得见"
 ↓
M5 规则抽屉           ← 能改规则
 ↓
M6 收口与增强         ← 本地独有记录 · 导出 · 加载全部
```

**为什么这个顺序**：前一步是后一步的**数据或能力前提**。
M2（引擎）必须在 M4（overlay）之前 —— 没有分类结果，overlay 就没东西可显示。
M3（对拍）紧跟 M2 —— **移植完立刻验**，别等 overlay 做完才发现引擎语义偏了。

## 三、每一步：做什么 ＋ 验什么

### M0 · 油猴骨架与地基

| 项 | 内容 |
| --- | --- |
| **做** | 元数据块（`@match https://www.bilibili.com/history*` · `@run-at document-start` · `@grant`）· `fetch` hook 骨架 · 最小可用验证 |
| **验** | ① 脚本在历史页**确实被注入**（console 打点）；② **能拦截到** `history/cursor` 响应且拿到完整 JSON；③ **不影响**原页面正常功能（能翻页、能播放） |
| **产出** | 一个能打印"我抓到了 N 条"的最小脚本 |

⚠️ **`document-start` 是硬要求** —— 必须在页面脚本执行**之前**装好 hook，否则拦截不到第一批请求。

⭐ **M0 是「可行性探针」，必须单独验收通过后才能进 M1**（附录 A 评估 K5 的结论）：
`fetch` hook 能否稳定装好、能否拿到完整响应 —— 这是**唯一可能让整个阶段需要重新评估**的卡点。
若 M0 就卡住，后面的存储/引擎/overlay 都无从谈起 ⇒ **不要和 M1 混在一起做**。

### M1 · 双存储（IndexedDB）

| 项 | 内容 |
| --- | --- |
| **做** | `raw` 仓库（**完整响应原样**，key = `bvid@view_at`）＋ `derived` 仓库（规范化字段）· 读写封装 · 容量与配额处理 |
| **验** | ① 抓到的 JSON **字段数与接口返回一致**（与 `raw` 层逐键对拍）；② 重复翻页**不产生重复记录**（幂等 upsert）；③ 刷新页面后**数据还在**；④ 大容量（数千条）不崩 |
| **产出** | 可持久化的本地库 |

⭐ **本步的硬约束**：`raw` 层**永不丢字段、永不淘汰**。
理由（原设计 §3.1）：Finder 现版 `raw_json` 只有 24 键且缺 `business`/`bvid` 等，
**已被实测证明"事后补不回来"**（`store.py:134` 记录了「`history/cursor` 只回近三个月」的硬约束）
⇒ **油猴必须在一开始就把完整响应存下来**，否则以后缺什么都没处找。

### M2 · 规则引擎 JS 移植（**最重的一步**）

| 项 | 内容 |
| --- | --- |
| **做** | 以 `engine.py`（542 行）为参考，移植到 JS |
| **必移植** | `default_rules` · `_derived` · `eval_condition`（含高级筛选器超集）· `eval_group` · `evaluate_rule` · `validate_rule`（冲突校验 C1–C3）· `classify` · `rules_hash` · `sort_value` · `apply_sort` |
| **不移植** | `load_rules_from_file`（Python 文件 IO → 换成 IndexedDB 读） |
| **验** | 见 **M3 对拍** |
| **产出** | `engine.js`（语义与 Python 版等价） |

⚠️ **两个已知的坑，移植时必须处理**（否则会偏离语义）：
① **`#41` 守卫**：`eval_condition` 对 `duration` 有「有值才判」守卫（`cur is None or <= 0` → 返 False，且**刻意不拦** `exists`/`empty`）—— JS 版必须**同样实现**，否则 `duration=0` 会被误判短视频。
② **`#42` 分段排序**：`apply_sort` 是**分段**实现（有值段按方向排 ＋ 缺值段**永远**追加末尾），**不是**简单 `sort(reverse)` —— 否则降序时缺值会跑到最前。

### M3 · ⭐ 引擎对拍验收（**本流程的核心防线**）

> **为什么单列一步**：引擎是油猴的**语义心脏**。它偏了，后面 overlay 做得再漂亮也是错的。
> 而对拍是**唯一能证明"JS 与 Python 语义等价"**的手段 —— 单纯跑通几个例子说明不了问题。

| 项 | 内容 |
| --- | --- |
| **做法** | 用**同一批**规则 ＋ **同一批**记录，分别喂给 Python `engine.py` 与 JS `engine.js`，**逐条比对输出** |
| **用例来源** | ① 复用 `dev/test_engine.py` 的 **114 项**既有用例（导出成 JSON 对拍夹具）；② 补充边界：`duration=0` / `duration=NULL` / 空规则 / 冲突规则 |
| **比对项** | `view`（三视图归属）· `skip_state` · `conflicts` · `dirty_count` · 排序后的**完整 kid 序列** |
| **通过标准** | **100% 一致**（不是"大部分一致"）—— 任何一条不一致都要查清是移植错还是 Python 版本身的问题 |

⭐ **这一步也是把 A1 那套"回退验证"经验用过来的地方**：
对拍通过后，**故意改坏 JS 版一处**（如拿掉 `#41` 守卫），对拍**必须立刻报不一致** ——
否则说明对拍本身是空转的（与 G5/G6 的行为锁同一个道理）。

### M4 · 原生历史页 overlay

| 项 | 内容 |
| --- | --- |
| **做** | 顶部筛选栏 · 每条记录的分类角标 · 命中项隐藏/置顶 · `MutationObserver` 跟随 SPA 重渲染补标 |
| **视觉参照** | ⭐ **照抄** `src/web/`（已按 B站风格定稿），不另起一套风格 |
| **验** | ① 角标**显示在正确位置**且不影响原页面点击；② ⭐ **翻页 ≥3 次后角标仍在、且不重复渲染**（`MutationObserver` 生效且幂等 —— 附录 A 评估 K2 给的验收项）；③ 筛选栏筛选后**条数与引擎结果一致**；④ 原页面**所有功能仍正常**（播放/删除/搜索） |
| **产出** | 能在 B站原页上"看得见分类"的脚本 |

⚠️ **SPA 跟随是这一环节最容易低估的点**：B站历史页是 Vue 单页应用，
翻页**不重新触发** `document-start` ⇒ 必须用 `MutationObserver` 补标，否则只有第一页有角标。

### M5 · 浮动规则抽屉

| 项 | 内容 |
| --- | --- |
| **做** | 规则管理（单活跃切换 · 新增空白/预设 · 二次调整 · 冲突提示）· 存 IndexedDB |
| **验** | ① 改规则后**分类结果立刻变**；② 冲突规则**能被提示**（C1–C3）；③ 刷新后规则仍在；④ **`rules.json` schema 与 Finder 一致**（可互相导入导出） |
| **产出** | 可在浏览器内管理规则 |

### M6 · 收口与增强

| 项 | 内容 |
| --- | --- |
| **做** | 本地独有记录（服务端已删）分组 ·「仍存于 B站 / 仅本地」标注 · 可选增强（加载全部 · 导出 JSON/CSV） |
| **验** | ① 本地独有记录**被正确识别**；② 导出文件能被 Finder 读回（schema 一致） |
| **产出** | 完整可用的油猴脚本 |

### ⛔ 贯穿全程的红线（每一步都不能违反）
