## 2. 四个系统性根因

> 后面的具体问题几乎都能归到这四条上。它们不是"某个函数写错了"，而是**架构层面缺失的约束**。

### R1 · 没有并发模型：全局可变状态 + 多线程 + 热重载，且全仓无锁

> ⛔ **判定不修**（2026-10-01）：事实成立，但本服务是**单用户本地工具**，无并发压力；真要做的最小成本是「reload 期加一把全局锁 + 请求读快照」，**不是**重写并发模型 —— 那属 `R4`（单文件）重构的范畴，与「连接即模式」阶段重叠。见 `F-H4`。

- `ThreadingHTTPServer`（`server.py:36–61`）下，`sync_state` / `autoskip_state` / `COVER_MAP` 是**模块级可变量**，被多线程请求同时读写。
- `store` 侧另有模块级缓存（`_RAW` / `_LAST_SOURCE`），并在 `reload_raw()` 时整体替换。
- ⑥ 热重载走 `importlib.reload`，**整体替换 store 模块对象** → 并发请求可能正持旧引用，或正在读 `_RAW` 的中途被换掉。
- 全仓**无锁、无版本号、无快照隔离**。

**后果**：撕裂读 / 半成品数据 / 竞态，且**不可复现、无日志**。

### R2 · 静默失败文化：`except Exception` 无日志，错误被伪装成「空数据」

> ✅ **已修（收窄版）**（2026-10-01）：**不做** 124 处全量改造，只覆盖「源读取 + 配置写入」链条（`store.py` 4 点 + `server.py` 5 点），把「失败」与「空」分开；`FileNotFoundError` 明确判为正常态、**不记**。见 `N-H1`。

- 实测 `except Exception`（含裸 `except:`）**50+ 处**：`store.py` 13 · `engine.py` 12 · `server.py` 20+ · `collector.py` 3。
  （2026-10-01 复核：按 `^\s*except` 宽口径实测 **server 87 · store 19 · engine 12 · collector 6**（合计 **124**；其中 `except Exception` / 裸 `except:` 族 **100** = server 67 · store 18 · engine 12 · collector 3）—— 原稿数量**低估**，故本条结论反而更强。注：**124 为修复后快照**，修复前约 110。）
- 绝大多数直接吞掉，返回 `{}` / `0` / 默认值。

**后果**：**"库读失败"与"真的没有数据"不可分**。`#37` 只是靠一条 diagnosis 横幅兜底了「路径配错」这一种；`store.py:436–470` 一带仍是空返回。

### R3 · HTTP 服务实际监听全网卡，且无鉴权 / 无 CSRF / 无 Origin 校验

> ✅ **已修**（2026-10-01）：绑定回退序由 `("::","0.0.0.0","127.0.0.1")` 改为 **`("127.0.0.1","::1")`**；横幅/日志改为**如实输出真实 `bind_host`**。见 `F-H1`。

- `server.py:2053–2058` 依次尝试 `::` → `0.0.0.0` → `127.0.0.1`，**先命中的是全接口**（`restart.log` 亦记录 `listen on 0.0.0.0:8765`）。
- 但启动横幅与文档都宣称 `127.0.0.1`（`server.py:2067`、`server.py:2090`、`README` §2）→ **暴露面被文案掩盖**。
  （2026-10-01 复核：`server.py:2090` 那行其实是**如实记录真实 `bind_host`** —— 正因如此才有了上面那条 `0.0.0.0` 铁证；真正"宣称 127.0.0.1"的是 **`2067`** 与 **`2077`**。）
- `do_POST` 不校验 Origin / Content-Type（`server.py:1760–1768`）。
  （2026-10-01 复核：Origin 校验**未做**，但**请求体**已不再静默退化 —— 见 `F-H3`。）

**后果**：同网段任何人都能读全部历史、改 skip/备注、触发抓取、`POST /api/apply` 重启服务；浏览器侧存在 CSRF / DNS-rebinding 面。

### R4 · 巨型单文件、职责混杂、重复模式

> ⛔ **判定不修**（2026-10-01）：这正是「连接即模式」要收敛的元问题，**应由阶段 2–4 的结构性改动消化**，不宜作为孤立补丁。见 `N-M1` / `N-M2`。

- `server.py` 2097 行同时承载 HTTP 层 + 全部路由 + 中继 + 重启链 + 备份策略 + 能力/策略层。
- `app.js` 2291 行，无模块拆分。
- 多处重复的 `fetch + toast + finally`（`app.js:2196–2258` 等）未抽象。

**后果**：改动半径大、回归面不可控（这正是"连接即模式"要收敛的那 12 处分叉的土壤）。

## 6. 一句话结论

功能闭环是完整的，风险**不在"缺功能"**，而在四件事：**并发无模型（R1）· 失败不发声（R2）· 监听面与文案不符（R3）· 单文件承载过多职责（R4）**。
