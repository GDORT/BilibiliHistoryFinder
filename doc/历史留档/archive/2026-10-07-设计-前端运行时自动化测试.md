## 一、目的（为什么非做不可）

### 1.1 补上四层可测性里**唯一"无手段"的那一层**

`dev/README.md` §6.1 的四层模型已诚实标注：纯逻辑 / 请求控制流 / 启动边界三层**已有手段**，
**前端层是"❌ 目前无手段"**。这不是"锦上添花"，而是结构性的**单点空白** —— 其余三层都测了，
只有"**渲染与交互**"这一层一条断言都没有。

### 1.2 锁定**只在交互层才暴露**的回归

有些缺陷**纯函数测得到、UI 测不到**；反过来，下面这些**只在"页面真的跑起来、真的点下去"时才暴露**：

| 行为 | 出处 | 纯函数/静态测试为何测不到 |
| --- | --- | --- |
| `#41` `duration=0` 不被误判短视频 | `dev/README.md` §6.5 | 静态护栏只验 `CAP_DOM` 选择器**存在**，验不了"点了筛选后**实际剩几条**" |
| `#42` 排序缺值**恒在末尾**（升/降序都不跑到最前） | 同上 | `apply_sort` 单测能验算法，但**表格实际呈现顺序**依赖 `buildQueryBody` → 端点 → `render` 全链路 |
| 阶段 4 能力渲染（`UNAVAILABLE_MODE="gray"` 置灰） | `log/2026-10-03-审查-阶段4前端落地.md` | 只验了 `CAP_DOM` 键存在；**"置灰数量与能力表一致"** 没验 |
| 横幅两档（`bad` / `warn` / `ok`）＋ `srcAct` 只在 `bad` 出现 | `app.js` `renderSourceBanner` | 静态标志在**源码里**，两档**切换行为**没人测 |
| `sync` 四态渲染：完成 / `skip`（非红） / `blocked`（红） / `running`（进度条） | `app.js` `applySyncStatus` | `plan_mode=skip` **刻意不复用失败样式** —— 这条"有意区分"极易被日后改回红色失败 |

> ⇒ **目的不是"把页面点一遍"，而是把这些"运行时行为契约"锁成断言** —— 与 §三 · 5
> "契约要用真实产出校验"同源：**驱动 UI 的就是真实端点响应**，一旦显示与响应脱节立即失败。

### 1.3 与既有静态护栏的关系（补位，不重复）

现有 `test_capabilities.T2.8` ＋ `test_api_contract.P6` 验的是**静态**（选择器/标志**存在**）。
A1 验的是**动态**（**点了会怎样**）。二者**互补**，A1 **不得**退化成"再抄一遍静态断言"。

## 二、定位与边界

### 2.1 测什么（In scope）

1. **加载完整性**：页面加载后**无 JS 运行时错误**（`pageerror` / `console.error`）。
2. **渲染结果**：列表条数、卡片字段（时长/时间/徽标）。
3. **能力→DOM 映射**：`applyCapabilities` 把不可用能力按 `CAP_DOM` 施加 `gray` 类。
4. **横幅两档**：`renderSourceBanner` 的 `bad`/`warn`/`ok` 与 `srcAct` 可见性。
5. **同步状态渲染**：`applySyncStatus` 的四分支（完成/`skip`/`blocked`/`running`）。
6. **交互联动**：排序（升/降、缺值位置）、筛选（含 `duration` 边界）、toast 文案。
7. **规则引擎的 UI 出口**：条件命中后列表归属（间接验 `#41`）。

### 2.2 不测什么（Out of scope，明确排除）

- **像素/视觉**：不做截图比对（无设计稿、成本高、收益低）。
- **跨浏览器**：只锁 1 个内核（Chromium / 本机 Edge），不做兼容矩阵。
- **性能/加载耗时**：不做 benchmark。
- **真实后端**：一律走**沙箱副本 ＋ 替身**（幽灵 Analyzer / 假 Analyzer / 夹具库），**零实网、零真实数据**。
- **阶段 6 之后的未来 UI**：本设计**以当前 `UB`（阶段 4 定稿）为准**；阶段 6 改 `UNAVAILABLE_MODE` 后再修订。

继承 `dev/README.md` §二 四条安全约定 ＋ §三 七条经验，**前端特有**补三条：

| # | 原则 | 来源 | 前端落地 |
| --- | --- | --- | --- |
| P1 | **拓扑同构** | §三 · 1 | 不把渲染逻辑抄进测试脚本；**真起服务 → 真开浏览器 → 真读 DOM** |
| P2 | **复制仓库跑真进程** | §三 · 6 | 复用 `verify_riskfix.py` 的 `copytree src/` ＋ 空 `data/` ＋ 随机端口 |
| P3 | **反例对照** | §三 · 3 | 每条断言尽量配"**不该成立**"的一侧（见 §六 每组的"反例"列） |
| P4 | **真实产出驱动契约** | §三 · 5 | 断言**对照 `/api/capabilities` 的真实响应**，而非硬编码文案 |
| P5 | **断言不藏环境前提** | §三 · 7 | 形态（standalone/combined）× 状态（skip/blocked/fail）**显式分流**，不假设"某形态一定出现" |

`dataset.sig` 的档位前缀。文案只在**必要时**做"包含关键词"的弱断言。

## 四、架构（三层）

```
[驱动层]  Playwright（dev/e2e/pkgs + browsers，已隔离）   ← 或退化为 CDP 直连本机 Edge
     │  open(随机端口)  →  等首帧
     ▼
[被测实例]  copytree src/ → 临时目录 + 夹具 data/ + 幽灵/假 Analyzer + 随机端口
     │  复用 verify_riskfix.py 的隔离拓扑；零真实数据
     ▼
[断言层]  python 脚本 dev/e2e/smoke_frontend.py
     · 复用 dev/ 既有 check/eq 风格（与 test_api_contract.py 同构）
     · 读 DOM（page.eval）＋ 读端点原始响应（真实产出）双向对照
```

- **驱动选型**：优先 **Playwright**（已下载、API 稳、可等 `networkidle`）；
  备选 **CDP 直连本机 Edge**（零额外依赖，但连接与等待要手写）——**同一断言层两种驱动可切换**。
- **被测实例拓扑**与 `test_api_contract.py` / `verify_riskfix.py` **完全一致**（同一条安全基线）。
- **不新造假后端**：Analyzer 用既有 `mock_analyzer.py` 思路；B站用既有 `BHF_API_BASE`。

## 五、夹具设计（前置 2 —— 最关键、也最容易做砸）

> 没有确定性夹具，"看到几条"每次都不同 → **断言无从写起**。这是 §6.4 判定"仍缺"的首因。

### 5.1 夹具内容

| 夹具 | 位置（沙箱内） | 要求 |
| --- | --- | --- |
| `data/bilibili_history.db` | 沙箱 `data/` | **固定 N 条**，覆盖**五分类**：`finished` / `auto_skip` / `stale` / `needs`（需观看）/ 其余 |
| `canonical_state.db` | 沙箱 `data/` | 固定 skip 状态（`auto_skip` 的依据） |

### 5.2 夹具硬约束

1. **条数固定且显式**：N 是**常量**（如 40），断言直接写 `== N`；不同测试函数用**子集**（按类型筛）而非改库。
2. **`duration` 长尾必须显式覆盖**：**既有 `0`/`null`，也有正常值** ——
   否则 `#41`（有值才判）与 `#42`（缺值排序）**没有触发样本**，测了个寂寞。
3. **各分类条数已知**：每类条数写成常量（如 `needs=10`），使"筛选后剩几条"可被判。
4. **生成可复现**：`dev/e2e/make_fixtures.py`（**确定性**：固定 seed / 固定列表，不用随机）——
   一次生成、进 `dev/e2e/`（`.gitignore`）或直接内联到测试脚本。
5. **永不写真实库**：夹具只写入**沙箱临时目录**的 `data/`，`copytree` 后覆盖，跑完 `rmtree`。

## 六、用例设计（首批断言清单）

> 每条标注：**依赖夹具 / 期望 / 反例（不该成立的一侧）**。首批约 6 组、**20–30 条断言**为合理起步量。

### G1 · 加载完整性

| 断言 | 期望 | 反例 |
| --- | --- | --- |
| 页面加载无 `pageerror` | 捕获数为 0 | （监控即反例：**任何 JS 报错都算失败**） |
| 列表渲染条数 | `== N`（夹具常量） | 不等于 N 即失败 |

### G2 · 能力 → DOM 映射

| 断言 | 期望 | 反例 |
| --- | --- | --- |
| standalone 形态：`remark/export/images/integrity` 的 `CAP_DOM` 选择器带置灰类 | 4 组均命中 | **combined 形态下同一组不得带置灰类** |
| 置灰**数量**与 `/api/capabilities` 的 `available=false` 项数一致 | 一一对应 | 数量不符即失败 |

### G3 · 横幅两档

| 断言 | 期望 | 反例 |
| --- | --- | --- |
| 独立形态（Analyzer 不可达） | `#srcBanner.class` 含 `bad`；`srcAct` **不** `hidden` | —— |
| `source.requested=local` | 档位为 `warn`；`srcAct` **hidden** | **bad 档下 `srcAct` 必须可见**（对称） |
| 一切正常 | 横幅 `hidden` | —— |
| `dataset.sig` | 前缀 `== 档位` | 同档同条数但**原因不同**时 sig 必须不同（T3-A 教训） |

### G4 · 同步状态四态（`plan_mode` 分流）

| 后端 `last` 形态 | 期望 DOM | 反例 |
| --- | --- | --- |
| `ok=true` | `#syncDone` 显示、类 `sync-done`、含"完成" | —— |
| `plan_mode=skip` | 类含 `sync-skip`、文案含"跳过"、**不得**含 `sync-fail` | **不得显示为红色失败**（阶段 4 的刻意区分） |
| `plan_mode=blocked` | 类含 `sync-fail`、文案含"阻断" | —— |
| `running=true` | `#syncProgress` 可见、进度条宽 = 计算值 | —— |

> 驱动方式：`page.evaluate(applySyncStatus, 伪造状态对象)` —— **直接喂四态样本**，
> 不依赖真跑一次同步（但样本字段**取自真实 `/api/sync` 响应的键名**，遵 P5）。

### G5 · 排序联动（`#42` 行为锁）

| 断言 | 期望 | 反例 |
| --- | --- | --- |
| 按 `duration` **升序** | 有值段递增，**`0`/`null` 段在末尾** | 缺值**不得**出现在最前 |
| 按 `duration` **降序** | 有值段递减，**缺值段仍在末尾** | 缺值**不得**跑到最前（`#42` 修的就是这个） |

### G6 · `duration` 边界（`#41` 行为锁，UI 出口）

| 断言 | 期望 | 反例 |
| --- | --- | --- |
| 规则含"短视频（`duration < 60`）"，夹具含 `duration=0` 的陈旧记录 | 该记录**不**归属"已跳过" | 它**不得**因 `0<60` 被误标（修前 435 条被误伤） |
| `exists` / `empty` 算子对 `duration=0` | 按**算子原义**判定（守卫不拦） | 守卫**不得**误伤 `exists`/`empty` |

## 九、判定标准（什么算"绿"）

1. **脚本退出码 0**，且断言总数与 `run_all.py`/文档**声明一致**（B3 回链）。
2. **两种环境**（带代理 / 无代理）都绿 —— 沿用 `run_all.py` 已固化的防线（P5）。
3. **零污染**：`data/`、真实库、真实配置**一字节不动**；沙箱跑完 `rmtree`。
4. **反例全部成立**：每条正例都配了"不该成立"的一侧，且该侧**通过**。
5. **失败可定位**：失败时能指出**哪条断言 / 哪个 DOM / 哪个响应字段**。

## 十、最小可行切片（MVP，建议落地顺序）
