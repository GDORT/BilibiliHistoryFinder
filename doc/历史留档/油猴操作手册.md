## 这是什么

把 Finder 的本地能力（规则引擎 / 分类 / 排序）**移植到浏览器里**，
直接作用在 B站历史页上，加角标、加筛选入口。

**不依赖 Analyzer** —— 数据来自页面自己发的请求，脚本只是"旁听"。

## 界面与显隐（v0.4.1 起）

脚本只加**一条顶部细栏** ＋ **两个悬浮面板**，都**默认关闭**，不遮挡你看视频/列表：

| 元素 | 位置 | 默认 | 怎么开 | 怎么关 |
| --- | --- | --- | --- | --- |
| 顶栏「BHF 历史增强」 | 顶部 34px 细条 | **常驻**（极窄，只显示统计读数） | — | — |
| **分类视图** | 左侧悬浮 | **关闭** | 顶栏「分类」 | 面板内右上 `×` |
| **规则抽屉** | 右侧悬浮 | **关闭** | 顶栏「规则」 | 面板内右上 `×` |

- 顶栏「分类」/「规则」是**开关按钮**，再点一次即关闭。
- 关掉的选择会**记住**：下次打开历史页不会自己弹出来。
- 想看当前状态，看顶栏那行读数：`N看完 · N跳过 · N搁置 · N待观看`。
- 角标直接打在原卡片上，不受面板显隐影响（面板关着照样有角标）。

> 显隐状态存在浏览器 `localStorage`（键 `bhf.ui.panels`），与数据存储无关，清缓存即恢复默认（关闭）。

## 一、探针怎么用（**需要你来做**）

### 1. 装

油猴（Tampermonkey）→ 新建脚本 → 把 `probe.user.js` **整份内容**粘进去 → 保存。

⚠️ 确认三个元数据没被改动：

```js
// @run-at       document-start     ← 硬要求：晚于这个时机就拦不到第一批请求
// @grant        none               ← 与页面共享 window，hook 才生效
// @match        https://*.bilibili.com/*
```

### 2. 跑

打开 **https://www.bilibili.com/history**（需登录），正常浏览、往下翻几页。

### 3. 一键导出（**就这一步，不用翻控制台**）

**点右下角角标** → 自动完成三件事：

1. 生成完整诊断报告
2. 复制到剪贴板
3. 弹出一个可手动复制的面板（剪贴板失败时的兜底，已自动全选）

把内容直接贴给开发者就行。角标本身也会实时显示状态：

| 角标 | 含义 |
| --- | --- |
| 🟩 **BHF 抓到 N 条 · 点我导出** | ✅ **K5 通过**，点它拿报告 |
| 🟥 **BHF 未通过 · 点我导出** | ❌ 有问题，点它看**具体是哪一步、为什么** |

报告里包含（**开发者需要的都在里面，不用你判断什么有用**）：

- **结论**：通过 / 失败，附原因和建议动作
- **分步结果**：hook 装载 → 见到请求 → 捕获响应 → JSON 解析 → 业务码，逐条 ✅/❌
- **抓到的响应**：`via`（fetch 还是 xhr）、每页条数、**顶层键**、**history 子对象键**
- **出现过哪些请求**：去重统计，标出哪些含 `history`（接口若变更，看这里）
- **时间线**：相对脚本启动的毫秒级事件
- **环境**：页面 URL、是否在历史页、是否已登录
- **告警**：脚本内部捕获的异常

> 💡 失败原因不是猜的：`code` 错误码按 `src/collector.py` 的错误码表映射
> （如 `-101` → 明确告诉你是登录态问题）。
> 这份诊断逻辑本身也有 7 个场景的自动测试兜底，见下方「机制层验证」。

## 二、判定

### ✅ 通过（角标变绿）

点角标、贴报告，直接进 **M0** —— 顶层键 / history 子对象键要据此确定 `raw` 存哪些字段。

### ❌ 不通过（角标变红）

报告里**已经写明失败在哪一步、为什么、该怎么办**，照着做即可。常见三种：

| 失败步骤 | 含义 | 怎么办 |
| --- | --- | --- |
| 第 2 步「见到目标请求」 | 页面根本没发这个请求 | 确认在 `/history` 且已登录、往下翻几页；报告里 `seenSummary` 会列出实际请求，据此判断接口是不是换了 |
| 第 3 步「捕获到响应」 | 见到请求但读不到响应 | 看报告 `warn` 字段（多为流式消耗 / 重定向 / 跨域） |
| 第 5 步「业务码」 | 接口返回错误码 | `-101` / `11000` = 先登录 B站再刷新；`-412` / `-509` = 被风控，等一会儿 |

**若 30 分钟内搞不定 → 整个油猴方案按约定重评**（K5 是唯一有这个地位的卡点）。

## 六、移植时的两个坑（M1 必看）

`engine.py` 里有两处反直觉实现，**漏掉就会语义偏离**：

1. **`#41` 守卫** —— `eval_condition` 对 `duration` 有「有值才判」守卫
   （`None` 或 `<= 0` → False，但**刻意不拦** `exists` / `empty`）。
   漏掉 ⇒ `duration=0` 被误判短视频（历史上误伤 435 条）。
2. **`#42` 分段排序** —— `apply_sort` 是**分段**（有值段按方向排 ＋ 缺值段**永远**追加末尾），
   **不是** `sort(reverse=True)`。写成后者 ⇒ 降序时缺值跑最前。

⇒ 所以 M2 的**对拍**是硬要求，不是可选项。

## 八、分类视图（M6）＋ 一个真实根因

### 为什么加这个

原先「分类结果」只以**角标**呈现，而 `needs` 按设计不显示角标 ⇒ 页面上通常只剩零星几个角标，
**看不出规则到底有没有生效**。M6 把分类结果变成**可读、可查**的东西（仍是 README 早已声明的"筛选入口"，非新增需求）：

| 位置 | 内容 |
| --- | --- |
| 顶栏 | `N看完 · N跳过 · N搁置 · N待观看` ＋ 悬停显示**逐条规则命中数** |
| 顶栏「分类」 | 打开分类视图面板：全部 / 已看完 / 已跳过 / 已搁置 / 待观看 五个 tab，列出标题·UP主·进度·时长，点标题新窗口打开 |

顶栏那行读数**实时更新**（每次入库后重算），所以"规则没命中"和"命中了但没显示"能一眼分开。

> 修过的一个真实 bug：`getRecords` 返回的是 **Promise**（`BHF.Storage.getAllDerived()`），
> 而 `viewRows` 只认数组 ⇒ 面板恒显示"暂无记录"（顶栏读数却正常，因为它自己 `.then()` 了）。
> 现已兼容 Promise/数组两种来源，`verify_views.py` 有回归护栏锁住。

### ⭐ 根因：只有「已看完」有角标（真实 bug，已修）

**现象**：真实历史页上几乎只出现"已看完"，其他分类全无。

**根因**：`Rules.load()` 返回的是**包装对象** `{rules:[...]}`，而引擎 `evaluate_rule(rec, rule, now)`
读的是 `rule.groups` —— 包装对象上**没有** `groups` ⇒ 循环空转 ⇒ 对所有记录返回 `null`
⇒ 除 `progress === -1`（已看完，走单独分支）外**全部落进 `needs`（不显示角标）**。

`bootstrap()` / `bootstrapAll()` / `mountViews.render()` / 顶栏 `refreshStat()` **都曾直接传包装对象**。

**修法**：统一 `BHF.Engine.get_active_rule(BHF.Rules.load())` 拆包后再传给引擎。
`verify_views.py` 里有 4 条**回归护栏**锁死这个坑（传包装对象必须判 null、传激活规则必须命中）。

### 护栏（为什么这次能抓到）

之前 146 项断言全绿却漏掉它 —— 因为测试**都用拆好包的 rule 或自己构造的规则**，
只有 `mountViews` 这条真实路径会踩到。教训：**测试要覆盖「从持久化读出规则 → 直接喂引擎」这条真实链路**，
否则单元测试全绿而线上失效。M6 新增的 4 条回归断言就是为此。

### 踩坑：`setActive` 收包装对象却按数组遍历

`RuleSet.setActive(rules, id)` 形参收的是 `{rules:[...]}` 包装对象（与 `Rules.load()` 同形），
但循环写成了 `for (i=0; i<rules.length; i++)` ⇒ `rules.length` 是 `undefined` ⇒ **循环体一次都不执行**，
"单活跃切换"静默失效（不会报错，只是点了没反应）。现已兼容两种入参，测试锁死不变量。
