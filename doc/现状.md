### 2.3 数据源主开关（`data_source.mode`）

| 取值 | 含义 | 主源 | 抓取执行 |
| --- | --- | --- | --- |
| `auto`（默认，实际生效 `analyzer`） | 优先 Analyzer，读不到记录时才降级本地 | Analyzer 主源 | 中继 Analyzer |
| `analyzer` | 强制 Analyzer | Analyzer 主源 | 中继 Analyzer |
| `local` | 强制 Finder 自身 | 本地库 | 本机 `collector.py` |

- **降级判据是「Analyzer 是否读到记录」，而非「库文件是否存在」** —— 避免路径配错时「假装有数据」。
- 两模式共用同一 `kid = (bvid, view_at)`，分类状态存于侧库 → **切模式不丢 skip / views / lists，不需要状态迁移**。
- 切换即时生效（服务端 `reload_all()`），**不需要重启**。

**抓取判据与策略层（现行）**

- `POST /api/sync` 的判据**不再是手切 `mode`**，而是 `probe_connection()`（`server.py`，全项目唯一做网络 IO 的地方）→ `store.decide_sync_plan(probe, policy, state)`（`store.py`，纯函数规则表 `R1`–`R6`）。
- 规则表产出 `{mode: full|incremental|skip|blocked, reason, owner}`：`owner=analyzer` 走中继转发，`owner=finder` 走本机 `collector.py`。其中 **`R5` 是前置安全闸门**：`owner=finder` 且自有凭证不可用 → `blocked`，不发任何请求。
- **`policy` 的现状（勿按"已落盘"读）**：`store.load_policy()` 会从 `data/source_config.json` 里读 `policy` 段，但**当前没有任何生产写方** —— `store.save_policy()` 只在单测里被调用 → 实测该文件恒为 `{"mode": …, "analyzer_db": …}`，**`policy` 段永远不会出现**，读取时一律回落 `POLICY_DEFAULT`：`{"prefer": "auto", "sync": "auto", "rules": {"full_cooldown_min": 10, "full_interval_days": 7, "gap_threshold_days": 30}}`。策略段真正落盘属**阶段 5** 形态。
- 另有**隐藏 override**（`policy.sync = full|incremental`）：不进 UI、不落盘，只在内存储存里被 `decide_sync_plan()` 读到 —— `POST /api/sync?full=1` 就是走它（前端「全量重建」按钮）。旧文件里的 `mode` 三态仍可被 `store.normalize_policy()` 兼容读取。
- **`mode` 三态（`auto` / `analyzer` / `local`）仍未删除** —— 读取类端点与前端设置面板沿用；三态 → 二态（删手切值 `analyzer`）随前端改造进行。
- `GET /api/capabilities` 返回三样东西：**能力表**（`fetch`/`sync`/`remark`/`export`/`images`/`integrity`/`backup`，逐项 `{available, owner, reason}`）＋ **连接事实** ＋ **本次同步计划预览** `plan{mode, reason}`。消费它的是新端点的调用方；前端仍走旧端点。
- 凭证状态值域已扩为 **`missing` / `present` / `valid` / `invalid` / `unknown`** —— `_finder_sessdata_status()` 默认**只做本地判定**（不联网），唯 `GET /api/finder-session-check` 显式联网探测（避免 5 分钟轮询打 B站）。

### 2.4 合并与折叠规则

- **合并键**：`(bvid, view_at)`（`_rec_key`）。初版误用 `kid` 合并（Analyzer `kid` 恒 0、Finder `kid`=oid）曾产生大量重复，**任何新增备份源必须先对齐主键**。
- **冲突解决**：`kid` 相同时 **Analyzer 优先**。
- **折叠（Plan B「折叠显示 + 状态聚合」）**：同一 `bvid` 的多次观看会话在展示层折为一条。

| 字段 | 聚合规则 |
| --- | --- |
| 展示字段（标题 / 封面 / 作者 / uri…） | 取 `view_at` 最大的一条（对齐 B站官网「最近一次观看」） |
| `progress` | **任一会话 `== -1` → `-1`**；否则取 `max` |
| `duration` | `max`（防御性） |
| `session_count` / `first_view_at` / `kids` | 会话数 / 最早观看 / 全部会话 kid（新字段） |
| 无 `bvid` 记录（live / article / pgc） | **不折叠**，原样保留 |
| 记录自身 `kid` | 仍为「最近一次」的 kid |

- `classify_record` 支持 **`kids` 多键命中**：`manual_skip / auto_exempt / archived` 命中**任一**会话即生效 → 同一视频重看产生新 `view_at` 后，既有跳过状态不会静默失效。
- `remark` 是 Analyzer 的**按会话**字段（`(bvid,view_at)` 定位），折叠后展示「最近一次会话」的备注 —— 属折叠的固有语义，非缺陷。
- **auto 模式何时跳过读主源（阶段 2 修正）**：`load_raw_records()` 只在**三条同时成立**时跳过 Analyzer 年表 —— ① 最近一次探测结论是「不可达」；② 该结论未过期（`ANALYZER_PROBE_TTL` = 300 秒）；③ **主源库文件的 mtime 不比本地库新**。任一条不成立都照读（**正确性优先于省一次 UNION**）。
  - 判据是「**文件**能不能读」而不是「**服务**能不能连」：读文件不需要 Analyzer 在线；迁移之后若 Analyzer 又写过主源（mtime 更新），它就可能含本地库没有的记录 / 备注，此时必须照读。
  - ⚠️ 「迁移后本地库 ⊇ Analyzer 记录、合并结果不变」只是**迁移那一刻**的时点事实，**不是不变量**（运行期没有任何把 Analyzer 新数据回灌本地库的机制）。

## 5. 统一数据契约（canonical schema）

**结论：统一「逻辑数据契约」，不强求「物理数据库引擎」。**

- **权威层 `raw`**：完整 `cursor` 响应 JSON 原样存储，`key = (bvid|oid)@view_at`（与 §2.4 的 `(bvid, view_at)` 是**同一个键的两种写法** —— 上游 JSON 用 `@` 串接、canonical 用二元组），永不丢字段。
- **派生层 `derived`**：规则引擎所需规范化字段集 ——
  `business` / `progress` / `duration` / `view_at` / `title` / `author_name` / `author_mid` / `bvid` / `uri` / `cover` / `kid` / `dt` / `live_status` + 派生 `progress_pct` / `view_at_age_days` / `skip_state`。
- 规则引擎与 UI **只面向 canonical `derived` 开发一次**；各数据源通过 storage adapter 映射进 canonical 形式。
- **实测校准**：canonical `derived` 以 Analyzer 34 列为基准；Finder 的 `raw_json` 仅 23 键（缺 `business/oid/bvid/cid/page/part/dt/main_category/remark`），**不是真·原始响应权威层**。

## 6. 规则引擎核心

- **输入**：canonical `derived`。`progress == -1` 表示已看完 → `progress_pct = 1.0`；`view_at_age_days = (now − view_at) / 86400`。
- **`rules.json` 结构**：**单 `active` 规则**（同一时刻仅一条，`server.POST /api/rules` 强制校验 C6）+ 多 `groups`（`match:"any"` = OR 语义，命中任一分组即按该分组 `action` 处理）。
- **求值算法**：`eval_condition`（单条件）→ `eval_group`（分组内 AND）→ `evaluate_rule`（返回 `(action,label)` 或 `None`；`progress == -1` 短路返回 `None`；**首命中优先**）。
- **四个互斥分类桶**（不变式 `finished + auto_skip + stale + needs == total`；`/api/query` 的 `counts` 即由这四桶 ＋ `total` 组成，**前端 tab 与桶的映射见 §8.1**）：

| 桶 | 含义 |
| --- | --- |
| `finished` | 已看完（`progress = -1`） |
| `auto_skip` | 命中 auto_skip 分组 |
| `stale` | 命中 stale 分组（久未观看） |
| `needs` | 未完成且未被跳过（待观看） |

- **跳过状态与优先级**：`manual_skip`（人工）> `auto_exempt`（取消自动跳）> `auto_skip`（引擎）。`needs` 有隐含 **95% 门**（`progress_pct ≥ 0.95` 归入 `auto_skip` 而非 `needs`）。
- **冲突校验 `validate_rule`**：返回 `{hard, soft, info}` —— C1 重复条件 / C2 互斥 action / C3 无效字段；C6 多 active 由 server 强制。
- **增量感知 `dirty_count`**：以 `rules_hash` 比对「已应用哈希」与当前规则，统计上次应用以来新增未套用条数；`rules_status()` 返回 `pending + dirty_count`。
- **默认规则**：5 分组（接近看完 / 误触 / 短视频碎片 / 直播回放 / 陈旧）；default 下 `auto_skip` 多为短视频碎片（`duration < 60`），`needs` 多为低进度长视频。
- `stale` 默认恒为 0 —— 由默认规则「首命中优先」+ 陈旧分组排最后导致（老视频先被短视频碎片命中），**非缺陷**，可调 `rules.json` 顺序让 stale 生效。

## 9. 备份与保留策略

- **端点**：`POST /api/backup` 用 `sqlite3` 在线 `backup()` 对 Analyzer 主源（`ANALYZER_DB`）+ 本地库做快照 → `data/backup/<时间戳>/` + `meta.json`；`GET /api/backups` 列表。
- **策略文件** `data/backup_policy.json`：`{auto: true, delta_threshold: 200, keep: 5}`（**手改**，无写入端点；**文件不存在时即用这组内置默认**）。
- **自动路径**：仅在 ②③ 与 `/api/sync` **拉取成功后**（`_after_data_pull`）检查「自上次备份以来新增条数 ≥ 阈值」；**首次（无备份基线）不触发**，由用户手点 ⑤ 建立基线。
- **手动路径**不受阈值限制，但**同样受 `keep` 约束**（`/api/backup` 后补一次 `_prune_backups`，并把 `pruned` 回传）。
- **定位**：Analyzer 宕机 / 库损坏 / 库被删时，Finder 仍有可浏览的本地一致副本，**不污染主源**。

## 10. 硬约束与原则

1. **源库全程只读**（`file:...?mode=ro`），绝不 INSERT / UPDATE / DELETE 源记录。
2. **唯一可写库 = `canonical_state.db`**（分类 / 视图 / 名单 / 批量），与源库物理隔离。
3. **只监听本机回环**（`127.0.0.1` / `::1`），不提供对外服务。
4. **默认形态下 Finder 不持凭证、不自抓**：抓取由 Analyzer 执行。**独立形态**（Analyzer 不可达）下由 `collector.py` 自抓 —— 依赖自有 SESSDATA，**当前实测已失效（`-101`）**；未补好前策略层 `R5` 直接判 `blocked`，不发任何请求。
5. **当前阶段作业约束**（验证 / 重构期间）：不启动对外服务；不对历史数据做拉取 / 更新类操作。
6. **验证手段**：① 只读端点实测 ② 进程内调用 + 隔离目录 ③ `dev/` 自动回归脚本 ④ 现场实测 ⑤ 整进程隔离副本验收（`dev/verify_riskfix.py`）。**当前 `dev/` 四个回归脚本全绿**（2026-10-02 复跑）：`test_capabilities` **196 项**（默认零 IO；`--live` 另打本机 8765 则为 **226 项**）· `regression_fallback` **7/7**（含 `/api/sync` 回退组 ＋ A1 缺基线标记组）· `regression_restart` 全部通过 · `verify_riskfix` **67/67**，均零污染。

- 折叠行为**主动对齐 B站官网**（同一视频只显示最近一次），**不**对齐开源 Frontend（后者不折叠）。
