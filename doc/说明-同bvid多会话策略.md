## 2. 问题清单（4 类，按严重度排序）

### 🔴 P0 — 折叠丢失「已看完」状态（**功能性错误，7 条**）

折叠规则是「只留 `view_at` 最大的一条」，而 `progress == -1` 才代表「已看完」。  
于是出现：

| bvid         | 标题              | 会话序列（view_at, progress）                      |
| ------------ | --------------- | -------------------------------------------- |
| BV1NGTQ6kExe | 老板再给我来碗忘情牛肉面    | (1784434258, **-1**) → (1786859756, **24**)  |
| BV1HDNy6yEPX | 【达尔文奖】罪犯报复休班宪兵… | (1784263029, **-1**) → (1787317304, **7**)   |
| BV1U4jY6DEDD | 【达尔文奖】印度蛇类专家…   | (1784127862, **-1**) → (1787317849, **265**) |
| BV1K47A6PEnL | 【达尔文奖】男子猛灌一瓶烈酒… | (1784126798, **-1**) → (1787317857, **0**)   |
| BV1Bb4CziETu | 当小狗犯错被逮着后       | (1782990381, **-1**) → (1789060003, **22**)  |
| BV1AEuC6pEHf | 【睡前消息1078】…     | (1786631488, **-1**) → (1789804499, **0**)   |
| BV1C13B6LEpb | 原创作者            | (1785494364, **-1**) → (1789377677, **11**)  |

**用户视角**：这 7 个视频我明明看完了，却被列进「需要观看」。**且在越用越多的趋势下会持续增长**（每多看一次没看完的视频就 +1）。  
**对照**：B站官网历史页保留**全部会话**，所以官网**没有**这个错误——「对齐官网行为」这个目标，**当前实现并没真正达成**。

### 🟠 P1 — 折叠后丢失会话详情（次数 / 累计进度 / 更早时间）

折叠只留一条，于是「这个视频我看了 5 次」这个信息消失了。当前无"展开历史会话"入口。

### 🟡 P2 — skip / archived 状态绑定在 `(bvid, view_at)`，会「随新会话漂移」

`store.py:300 classify_record()` 以 `kid` 查侧库。若某 bvid 被 `manual_skip`，之后再看一次 →  
**新的 `view_at` 产生新 kid → 旧 skip 不生效 → 该视频重新出现**，用户会认为"跳过失效了"。  
（实测当前**孤儿状态 0 条**，即"被折叠掉的旧会话里带 skip/archived 的"暂为 0，所以**目前无实际影响**；但 P0 修复后若保留多会话，这条会立刻变成活跃问题。）

### 🟢 P3 — 无 bvid 记录不折叠

22 条（live/article/pgc）。**实测 (business,view_at) 全唯一，本来就不重复** → 当前"不折叠"策略**正确，无需改动**。

## 3. 策略方案（三档，建议选 B）

### 方案 A — 保持现状（只折叠显示）

- 工作量：0
- 代价：P0 的 7 条误判**永久存在且持续增长**；「对齐官网」名不副实。

### ✅ 方案 B — 「折叠显示 + 状态聚合」（**推荐**）

折叠时**不简单取最后一条，而是聚合出展示态与判断态**：

| 字段                   | 聚合规则                                   | 理由                                        |
| -------------------- | -------------------------------------- | ----------------------------------------- |
| `view_at`（展示用"最近观看"） | `max(view_at)`                         | 与官网"最近一次"一致                               |
| **`progress`（判断用）**  | **`max(progress)`，但 `-1` 视为最高（已看完优先）** | **修 P0**：任一会话看完 → 整体视为已看完                 |
| `duration`           | 原始 last-write（实测 0 条差异，可不聚合）           | 保持简单                                      |
| `session_count`（新增）  | `len(sessions)`                        | 支撑「看了 N 次」展示与重看分析                         |
| `first_view_at`（新增）  | `min(view_at)`                         | 支撑"跨天重看"                                  |
| **`kids`（新增，全量会话键）** | 保留全部会话的 kid 列表                         | **修 P2**：skip/archived 查询改为"任一 kid 命中即命中" |
| 其余字段                 | 取 `view_at` 最大那条                       | 标题/封面/UP 等以最近一次为准                         |

**副作用评估**：`store.py` 改动集中在一个函数（`_fold_latest_by_bvid`），前端**零改动**  
（`session_count` 可先不展示，之后自愿加）。**skip 键语义变更需同步 `classify_record`**——  
即 `state.get(kid)` 扩展为「遍历 `kids` 找任一命中」。这是唯一的联动点。

### 方案 C — 双轨（折叠 vs 全量可切）

在方案 B 之上，视图加一个开关「每视频一条 / 全部会话」。

- 好处：保留"官网一致"默认，同时满足"我要看全部会话"。
- 代价：前端视图/分页/计数三处联动，工作量明显大于 B。**建议 B 稳定后再评估。**

## 4. 「已看完优先」的判定，是否要更保守？

`progress == -1` 在 B站语义上是「看完」，但存在**进度被重置**（重看时从 0 开始）的场景。  
方案 B 的 `-1` 优先会导致：**重看中（progress=11）但历史上看完过 → 显示"已看完"**，  
于是它**不再出现在"需要观看"**&#x91CC;。这更符合"我看过了"的直觉，**但会漏掉"我想重看"**。

→ 因此建议**同时记录 `rewatch` 标记**（`session_count > 1 且 最新 progress != -1`），  
供未来「重看列表」使用。**当前阶段只做 P0 修复，不做重看功能**。
