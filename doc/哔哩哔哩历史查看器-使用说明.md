# B站历史查看器 — 使用说明

> 面向使用者。本文档描述**当前已实现功能**的实际操作方式；设计背景与评估见同目录《哔哩哔哩历史查看器-原型方案.md》。
> 更新日期：2026-07-23。适用版本：本地 Web 版（零第三方依赖，纯 Python 标准库）。

---

## 1. 它能做什么

把你 B站账号的**观看历史**拉到本地、长期留存，并用一个类 B站网页端的界面浏览、搜索、筛选，找出**还没看完**的视频继续看。

核心能力：
- **本地留存**：历史记录存进本地 SQLite，官方接口只保留近段，本工具永久保存。
- **网页端式浏览**：封面 + 标题 + UP主 + 相对时间 + 进度条，可点击跳转 B站观看。
- **「需要观看」视图**：自动筛出"还没看完"的视频，并支持标记"不需要看"。
- **自动跳过规则（续看规则）**：按进度 / 时长 / 类型 / UP主等条件批量标记"不需要观看"，规则存于 `data/rules.json`、在 ⚙ 右侧抽屉中编辑。
- **批量操作**：批量跳过、恢复、隐藏。
- **增量同步**：首次全量建基线，之后只拉新记录，快且不踩限流。

## 2. 首次运行

### 2.1 准备登录态（SESSDATA）
1. 用浏览器登录 B站（bilibili.com）。
2. 按 `F12` → **Application（应用）** → 左侧 **Cookies** → 选 `https://.bilibili.com` 域名。
3. 找到名为 **`SESSDATA`** 的条目，复制它的 **Value**（一长串字符）。
4. 打开仓库根的 `config.json`，把值填进去：
   ```json
   {
     "SESSDATA": "这里粘贴你的SESSDATA值",
     "db_path": "data/bilibili_history.db"
   }
   ```
   > ⚠️ SESSDATA 是登录凭证，泄露等于别人能登录你的账号，**请勿分享、勿提交到公开仓库**。它也会过期（几天到几十天不等），过期后同步会失败，需重新按上面步骤取值替换。

### 2.2 启动与打开
在仓库根目录执行：
```bash
# 1) 拉取历史（首次会全量建基线；之后可只跑 Web 服务，点界面"同步数据"即可）
python collector.py --config config.json

# 2) 启动 Web 服务（默认端口 8765）
python server.py
cd D:\Programs\Share\BilibiliHistoryFinder && python src/server.py
```
浏览器打开 **http://127.0.0.1:8765** 即可使用。（前端改动读盘即生效，改完刷新页面即可，无需重启服务。）

- **类型 tab（综合 / 视频 / 直播 / 专栏）**：按内容类型筛选。

- **筛选 ▾（浏览筛选）**：点开"筛选"popover，设置时长 / 时间 / 设备 / 含存档，**仅对当前列表生效、不落库**，刷新页面即还原（见 §5）。
- **搜索框**：按标题或 UP主名实时搜索。
- **⚙（续看规则）**：点齿轮图标从右侧滑出"续看规则"抽屉（见 §7）。图标上两个角标：橙色圆点＝有已保存但未应用的规则改动（**待应用**）；数字＝自上次应用以来可能命中规则却未标记的新记录数（**脏计数**）。

> 设计要点：原本塞在同一个 ▾ 里的"浏览筛选（时长/时间/设备）"与"续看规则（写库 auto_skip）"现已拆开——浏览筛选是临时、不落库的"本次怎么看"，留在工具栏左侧的 **筛选 ▾**；续看规则是长期、写库的批量判定，收进右侧 **⚙ 抽屉**，默认隐藏、需要时滑出，体验接近 B站原版。

## 4. 同步数据

- **同步数据（增量）**：点一下即开始。有基线时自动**只拉取新记录**（比上次同步更晚的），快、省、不踩限流。顶部会出现**进度条 + 步骤文字**（含"同步中断，正在重试"等），完成后显示"✓ 同步完成"，并刷新"数据 vX · 更新于 …"。
- **全量重建（强制全量）**：点一下强制从头拉全量。用途：
  - 重新校准"仅本地存档"标记（增量不捕获 B站端的删除，见 §9）；
  - 刷新封面。
  - 平时不必用，发现"有些在 B站已删的视频还在列表里"时点一次即可。
- **首次必须全量**：清空库或换机器后第一次，会自动全量建基线（无需手动点全量重建，点"同步数据"也会自动识别无基线而转全量）。

## 5. 浏览与筛选

- **左侧时间导航**：今天 / 昨天 / 近一周 / 一周前 / 一个月前，点击即按观看时间筛选。
- **筛选 ▾（浏览筛选 popover）**：点工具栏"筛选 ▾"展开，设置**临时浏览条件**（不落库、不写盘，刷新页面即还原）：
  - **时长**：全部 / 10分钟以下 / 10–30分 / 30–60分 / 60分钟以上。
  - **时间**：全部 / 今天 / 昨天 / 近一周，或自定义起止日期。
  - **设备**：全部 / 设备A(dt=2) / 设备B(dt=3)。
    > ⚠️ B站未公开 `dt` 与具体设备（PC/手机/平板/TV）的对应关系，当前标签为占位符，仅作分组参考，不声称已识别真实设备。
  - **含存档**：勾选后把"B站端已删、仅本地留存"的记录也显示出来（原独立开关，已并入浏览筛选）。
- 浏览条件与顶部类型 tab、视图 tab、搜索、时间导航**叠加生效**（取交集）。
- **与规则筛选的区别**：浏览筛选只是"本次怎么看"，**不写库**；要长期批量标记"不需要观看"请用 ⚙ 续看规则（见 §7），那才会写入 `auto_skip`。

## 6. 「需要观看」与跳过（三态）

「需要观看」视图 = **还没看完**（进度 < 95% 或未完成）且**未被规则自动跳过**的视频。

每条记录的"跳过"状态有三种，且**只可能处于一种**：

| 状态 | 含义 | 怎么产生 |
|---|---|---|
| 空（默认） | 正常参与"需要观看" | 初始 |
| 手动跳过 | 你手动标记"不需要看" | 卡片"不需要看?"按钮 |
| 自动跳过 | 规则判定"不需要看" | ⚙ 续看规则抽屉里"应用规则" |

**手动跳过（在「需要观看」视图下操作）：**
- 卡片标题行出现 **"不需要看?"** 按钮（替代原来的删除按钮，更醒目）。
- 点击 → 标记为跳过，按钮就地变为 **"取消跳过"**，卡片**保留在「需要观看」视图**（按正常样式显示，不消失），封面右上角出现粉色 **"已跳过·手动"** 徽标。
- 点"取消跳过"或点徽标即可反悔。
- **在任何视图**（含完整历史），封面的"已跳过·手动"徽标都**可点击取消**。

> 跳过**不影响观看进度**：同步时不会因"重头看一小段"把已看完/已判定的进度回退（进度粘性保护）。

## 7. 自动跳过规则（续看规则，批量判"不需要看"）

点工具栏齿轮图标 **⚙**，从**右侧滑出"续看规则"抽屉**（默认隐藏；打开时**屏蔽同步与全量**，避免编辑期间抢库）：

- 规则存于 `data/rules.json`，可在抽屉内增删改分组与条件；**同一时刻仅一条规则 `active` 生效**（可维护多条规则，但只有被勾选"激活"的那条生效）。
- 每个规则由若干**分组**组成，每分组含若干**条件**（字段 / 运算符 / 值），命中任一分组即按该分组的动作处理：
  - `auto_skip`（自动跳过）：标记为"不需要观看"，写入 `auto_skip=1` 与命中原因 `auto_skip_reason`。
  - `stale`（已搁置）：单独一类，写入同一列但原因以 `stale::` 前缀区分，归入"已搁置"视图。
- 可用字段：进度百分比 `progress_pct`、已看秒数 `progress_sec`、总时长 `duration`、类型 `business`、UP主 `author_name`、UP主ID `author_mid`、标题 `title`、仅本地存档 `archived_only`、距今天数 `view_at_age_days`。
- 运算符：`>= <= > <`、`between`(区间)、`in`/`not_in`(逗号分隔集合)、`contains`(包含)、`==`。
- 抽屉**默认只展开"生效中"的规则卡片**（来自 `rules.json`）；其余未生效规则折叠在下方，点卡片头可展开做**二次调整**。支持实时**冲突校验**（保存时若有硬冲突会拒绝并提示）。
- 抽屉底部提供两个"新建"入口：**＋ 新建空白规则**（自行添加分组/条件）、**＋ 新建预设**（把当前生效规则**尚未覆盖的类别/类型**打包成一套规则直接加入，可随后二次调整；若类别已全部被当前规则覆盖则该按钮置灰）。

**两个动作（关键区别）：**
- **保存配置**：把当前规则写入 `rules.json`，但**不重算** `auto_skip`；此时齿轮图标出现**橙色「待应用」圆点**（表示有已保存但未应用的改动）。
- **应用规则**：先保存、再对**全量记录**重扫并写 `auto_skip`/`auto_skip_reason`（等价于一次全量效果，与当前处于哪个视图无关）。运行期间按钮禁用 + 进度条轮询，且与同步任务互斥（`_job_running()` 守卫）。应用前会弹窗显示将标记的跳过/搁置条数（含将覆盖的手动标记数）供确认。应用成功后「待应用」圆点消失、脏计数归零。

**退出抽屉（X / Esc / 点遮罩）三者等价：**
- 若抽屉内有**未保存**的编辑，会提示"有未应用的规则改动，退出将丢弃？"——确认后从服务端恢复编辑前状态（不写库）；
- 若已点过"保存配置"（改动已落盘但待应用），关闭不丢弃已保存配置，仅收起抽屉，「待应用」圆点保留直到你"应用规则"。

**状态角标（齿轮图标上）：**
- 橙色圆点＝**待应用**：`rules.json` 的哈希与"上次应用记录"不一致，即存在已保存未应用的规则改动。
- 数字＝**脏计数**：自上次成功应用规则以来，`view_at` 更晚、且尚未被跳过/看完的新记录数（可能命中新规则却还没标记）。点"应用规则"后归零。

**auto 覆盖 manual**：应用规则时，命中的记录会被标为自动跳过并清掉手动标记（"最后操作优先"）。手动标记仍可随时在「需要观看」视图或点徽标反悔。

完成后顶部提示"已应用规则：N 条跳过 / M 条搁置（覆盖手动 K 条）"。

## 8. 批量操作

1. 点顶部 **「批量」** 进入批量模式：每张卡片左上角出现勾选框，顶部出现批量工具条。
2. **动作下拉框随当前视图自动变化**（工具条上有"视图：全部 / 需要观看 / 已跳过 / 已搁置"标签）：
   - **全部 / 已跳过 / 已搁置 视图**（非「需要观看」）→ 只有 **「删除选中（隐藏）」**：勾选后应用 = 在当前会话隐藏（刷新页面会恢复，不删数据）。
   - **「需要观看」视图** → **「跳过选中」/「恢复选中」**：对应单卡"不需要看?"按钮。
3. **可勾选集合随模式限定**（显眼提示）：
   - 删除模式：所有卡片都可勾。
   - 跳过模式：仅**未跳过**的可勾（已跳过灰显禁用）。
   - 恢复模式：仅**已跳过**的可勾（未跳过灰显禁用）。
4. **全选可操作**：一键勾选当前模式下所有可操作项。
5. **应用(N)**：执行当前动作；**退出**：离开批量模式。

## 9. 卡片上的标记含义

| 标记 | 位置 | 含义 |
|---|---|---|
| 直播中（红）/ 专栏（蓝）/ 未开播（灰） | 封面角标 | 内容类型状态 |
| 已看完 | 封面右下 | 进度已 100%（progress = -1） |
| 观看时长 / 视频时长 | 封面右下 | 如 `12:30 / 45:00`，未看完时显示 |
| 进度条 | 卡片底部 | 已看百分比 |
| 已跳过·手动（粉） | 封面右上 | 你手动标记"不需要看"，**可点击取消** |
| 已跳过·自动（橙） | 封面右上 | 规则判定"不需要看"，**可点击取消** |
| 仅本地存档 | 封面左下 | B站端已无此记录、仅本地留存；存档状态**仅初始全量校准** |
| 🗑（完整历史视图） | 标题行 | 删除 = 本次会话隐藏，刷新恢复 |

相对时间格式：`今天 11:20` / `昨天 11:20` / `MM-DD HH:MM`。

## 10. 数据文件与备份

数据都在仓库 `data/` 目录：

| 文件 | 作用 |
|---|---|
| `bilibili_history.db` | 主数据库（全部历史记录 + 跳过标记） |
| `config.json` | 配置，含 `SESSDATA` 登录态 |
| `rules.json` | 续看规则（替代旧 `filters.ini`；由 ⚙ 抽屉编辑，不直接手改） |
| `sync_progress.json` / `sync_result.json` | 同步进度与完成判定 |
| `auto_skip_progress.json` | 规则应用进度（运行时产生） |
| `covers/` | 封面图片缓存 |

> 💡 **备份建议**：`bilibili_history.db` 是你全部留存数据的唯一载体，损坏或误删即永久丢失。重要前请复制该文件（可带日期命名，如 `bilibili_history.db.2026-07-23.bak`）。`config.json` 含凭证，备份时注意保密。**（一键备份/导出功能计划在后续阶段实现，见原型方案 3B.10。）**

## 11. 常见问题（FAQ）

**Q：点"同步数据"后一直失败 / 没新数据？**
A：最常见是 **SESSDATA 过期**。打开浏览器重新取 `SESSDATA` 值，替换 `config.json` 里的旧值，再同步。当前前端对过期仅以同步失败体现，暂无专门提示（后续阶段会加，见 3B.9）。

**Q：我在 B站删了某条历史，为什么这里还在？**
A：增量同步**无法发现 B站端的删除**（接口不返回已删项）。点一次 **「全量重建」** 即可重新校准"仅本地存档"标记——真正在 B站已删的会标上"仅本地存档"徽标（仍保留本地，永不硬删，因为留存是目的）。

**Q：标记"不需要看"后，下次同步会不会被覆盖？**
A：不会。手动/自动跳过状态在同步中是**粘性**的，不会被新拉取覆盖，也不会回退其进度。

**Q：应用规则后，我之前手动标记的没了？**
A：正常——规则"最后操作优先"，会覆盖手动标记。想保留手动标记，可取消对应规则或不对该类应用；已覆盖的也可在「需要观看」视图或点徽标随时反悔。

**Q：齿轮 ⚙ 上的圆点和数字是什么？**
A：圆点＝**待应用**：你点过"保存配置"但还没"应用规则"，`rules.json` 与上次应用的记录不一致，改动尚未生效；数字＝**脏计数**：自上次应用以来又来了一些可能命中规则却还没标记的新记录。点"应用规则"后两者都会清零。编辑中直接关掉抽屉（X/Esc/遮罩）只丢弃**未保存**的草稿，已保存的"待应用"配置不会丢。

**Q：删除按钮只是隐藏？**
A：默认"删除"= 本次会话隐藏（刷新恢复），不做硬删，符合"留存"初衷。要按规则批量剔除，请用 ⚙ 续看规则并「应用规则」（见 §7）。

**Q：为什么"设备"筛选只显示设备A/设备B？**
A：B站未公开 `dt` 与真实设备的映射，当前为占位标签（见 §5）。真实设备名映射为后续阶段任务（原型方案 3B.8）。

## 12. 已知限制（小结）

- 单账号；多账号为后续阶段（3B.4）。
- SESSDATA 过期需手动更新，暂无前端提示/重填 UI（3B.9）。
- 无一键备份/导出（3B.10）。
- 设备类型仅为占位标签（3B.8）。
- 深链 `bilibili://` 未做，网页链接已满足"定位+观看+回写"（3B.7）。
- 同步内自动套用规则暂缓，当前以"应用规则"为统一重校准入口（3B.6）。
