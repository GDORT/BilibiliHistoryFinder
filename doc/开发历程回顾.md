## 一、项目怎么走到今天

### 1.1 起点与三个前提

项目最初是一个"能不能把 B站 1000 条 / 3 个月的限制打破"的想法。真正决定形态的是三条外部约束：

| 约束 | 后果 |
| --- | --- |
| B站历史接口**只返回近三个月** | 数据必须**本地留存**才可能"永久"拥有 ⇒ 必须有一个自己的存储 |
| 抓取需要登录凭证，而凭证不便分发给多个程序 | ⇒ **只有 Analyzer 持凭证**，Finder 一律只读 |
| Python 标准库足够 | ⇒ 零依赖、零构建，`start.bat` 双击即用 |

### 1.2 五个阶段

| 阶段 | 做了什么 | 状态 |
| --- | --- | --- |
| **0** | 冻结数据契约（canonical schema），把规则引擎从 `server.py` 抽成独立纯逻辑模块 | ✅ |
| **1** | 「连接即模式」——把"用哪个数据源"从一次性决策变成**运行时事实** | ✅ |
| **1.5** | D 缺口（约 140 行功能补齐：风控码表 / 本地导出 / 删本地 / 凭证探测） | ✅ |

## 二、八条设计决策（ADR 全集）

> 这些是"不走那条路"的决定。**每条都保留了当时的反对意见和代价**，改之前先读。

### 1. 源库全程只读，分类状态只落独立侧状态库（2026-08-24）

**决定**：所有源库一律 `file:...?mode=ro` 打开，绝不写；分类/整理状态只写 `data/canonical_state.db`，与源库物理隔离。

**为什么**：源库是上游 Analyzer 的产物，随时可能被重建或覆盖。就近写回会把状态生命周期与上游绑死。
**代价**：多一个库要备份。
**意外收获**：`kid = (bvid, view_at)` 因此成为跨源稳定的键 ⇒ **切换数据源不需要迁移状态**。

### 2. 移除 `BHF_PORT`，端口只由配置文件决定（2026-09-25）

**决定**：删除为隔离测试临时加的端口环境变量覆盖，端口只读 `config.json` 的 `web_port`。

**为什么**：该覆盖只为一次性测试而设，留下它等于让"端口"有两个真相源，排查"是不是有两份实例"时多一条隐蔽分支。
**要换端口 → 改配置文件。**

### 3. `span_peak_days` 由同步成功后写回，在此之前 R3 恒不触发（2026-09-26）

**决定**：`span_peak_days` 峰值由"每次成功同步后写回 `meta`"维护。写回未落地前，R3 恒为 `None` → 保守不触发。

**为什么**：R3 原判据"缺口 = 主源条数 − 本地条数"是错的——2452 vs 134 的差异来自 B站三个月窗口，是**结构性差异不是缺口**，会每 7 天白跑一次全量（而全量同样补不回 2020–2024）。宁可"该触发时不触发"，也不要"把结构差异当成缺口"。
⚠️ **写回至今未实现 ⇒ R3 恒不触发是有意保守，不是 bug**，别去"顺手修"。

### 4. 保留 `collector.py`（2026-09-26）

**决定**：不删。它写的是自有 Finder 库（不是源库），不违反只读原则。

**为什么**：它是"Analyzer 缺席时的降级自持能力"的落地件。删了会让独立形态彻底失去抓取能力。删除属方案级改动，收益（少一份维护）不抵风险。
**代价（明说）**：承认"失效凭证路径仍可被触发"这一已知遗留。

### 5. 保留 `mode=local` 分支（2026-09-26）

**决定**：保留。`local` 表示 Finder 用自己的库与凭证。

**为什么**：Analyzer 没装/没启动时 Finder 仍可用。两模式共用同一个 `kid` ⇒ 切换零成本。
**细节**：`auto` 的降级判据是"Analyzer 是否**读到记录**"，**不是**"库文件是否存在"（避免路径配错时假装有数据）。

### 6. 暂不拆中继（2026-09-26）

**决定**：保留 `adapter_analyzer.py` 与 `server.py` 的转发基础设施（约 500 行），**不执行**轻量化方案的第 5 步拆除。

**为什么**：① 连接即模式把"要不要切形态"变成运行时事实，可以先让两种形态共存；② 保留中继时切换**可逆、零成本**（关掉 Analyzer 即自动独立），拆除**无退路**；③ 轻量化的收益是"形态"不是"代码量"；④ 日后要删时能力层已能做门控，删起来更安全。
**关联**：与决策 4、5 同向 —— 三者共同构成"**不删代码、靠能力层门控**"的路线。若确需拆除中继，**必须先重开这条决策**。

### 7. 油猴阶段独立（2026-08-24 → 2026-10-09 复工）

**决定**：油猴脚本（方案 D）**独立成一个阶段**，与前后端解耦。

**为什么**：① 它复用 `engine.py` 已验证的语义基准 ⇒ 移植风险低，无需抢时间；② 它是**新工程级**工作（1500+ 行 JS），不是收尾补齐；③ 与前后端轴解耦，变更不污染已稳定的主方案。
**已发生**：2026-10-09 该阶段执行完毕，产出 `src/userscript/` ＋根产物（0.4.1），见 [`油猴脚本.md`](油猴脚本.md)。

### 8. D 缺口独立成阶段 1.5（2026-10-01）

**决定**：约 140 行「功能补齐」（风控码表 / 本地导出 / 删本地 / 凭证探测）独立成一阶段，插在阶段 1 与 2 之间。

**为什么**：它既不属于阶段 1（规则引擎）也不属于阶段 2（抓取单入口），并入任一侧都会让"完成标志"含混。而且这几件事**同源**（都是"独立形态下缺的能力"），且**纯增**、不触碰既有路径。

## 四、踩过的坑与由此定下的写法

> 这一节是本项目**最该被继承**的部分。每条都是真实事故，不是理论。

### 4.1 判据类

**① 判断"规则会怎么判"必须重算，不能读已落库的分类值。**
已落库的 `auto_skip` 只是**某次历史时点的结果**。实测：读落库值显示"未被接住 390 条（8.8%）"，用规则重算同一批记录却有 **435 条（94.2%）命中** —— 因为规则从未在全量上重跑过。差了一个数量级。

**② `duration` 的「有值才判」守卫不能拦 `exists`/`empty`。**
`duration = 0` 曾被规则误判成"短视频碎片"，**误伤 435 条**。守卫刻意只拦数值判据（`None` 或 `<= 0` → False），`exists`/`empty` 原样放行。

**③ 降序排序必须分段，不能写 `sort(reverse=True)`。**
`apply_sort` 的正确语义是：有值段按方向排 ＋ **缺值段永远追加末尾**（升序降序都一样）。写成 `sort(reverse=True)` ⇒ 降序时缺值跑最前。

### 4.2 数据源与凭证

**④ B站详情接口 `/x/web-interface/view?bvid=` 无需 SESSDATA。**
2020–2025 那批 `duration` 全 0，一直以为是接口限制；实际是**当年采集时没落盘**。Analyzer 侧原始 JSON 也已被清理。真正的路是详情接口——它按 bvid 查、不受三个月窗口限制、**零风控额度**。最终 363 条补全 344 条（94.8%），剩下 19 条是稿件已删（不可恢复）。

**⑤ 找数据要先找对上游。**
判"数据是否存在"时只查了 Finder 侧 `raw_json` 就下结论"采集时压根没存"—— **漏了 Analyzer 侧的原始 JSON 才是权威**。结论方向完全相反。

**⑥ 两侧 SESSDATA 有三个坑**：配置在 `_internal/config/config.yaml`（不是 `config/`）；Finder 的键是**大写** `SESSDATA`；两侧值不同步（一边失效另一边仍有效）。

### 4.3 测试写法

**⑦ 拓扑必须与生产同构。**
要测写在 HTTP handler 里的逻辑，就真起 handler 发真请求，**别把那段 `if` 抄进脚本** —— 抄出来的是副本，线上照错。
实例：某测试最初直接在主线程调被测函数，天然拿到预期结果，**放过了真 bug**（生产里它在守护线程，退出码被吞成 0）。

**⑧ 优先"内存覆盖"而不是"改磁盘配置"。**
配置优先级若支持模块级内存覆盖，测试时只改内存即可，省掉"改配置 → 必须还原"整步，风险从 🔵 降到 🟢。

**⑨ 必须有反例对照。**
只测"该触发时触发了"不够 —— 一个永远返回 `true` 的实现也能通过。要同时测"不该触发时不触发"。

**⑩ 假样本测不出键名漂移，契约要用真实产出校验。**
单测里自己构造的 dict 只能证明"算法对"。实例：生产代码把字段名从 `sessdata` 改成 `state`，而单测样本两个名字都填了 ⇒ **7 个单测段全绿**。
规则：**凡有"两侧约定"的结构（probe ↔ 能力层、请求 ↔ 响应），必须有一条断言拿真实产出驱动消费方。**

**⑪ 要测"启动期行为"，就把仓库复制一份再跑真进程。**
绑定地址、`ensure_rules()`、`reload_all()` 这些只在 `main()` 里跑一次的东西，进程内 patch 测不到。做法：`copytree src/` 到临时目录 ＋ 空 `data/` ＋ 空闲端口 ＋ `ANALYZER_DB` 指向沙箱内不存在路径 ⇒ 整个实例自然隔离，**一行生产代码都不用改**。
配合 `netstat` 做独立于被测代码自称的核对 —— 这是唯一能证伪"横幅说 127.0.0.1、实际绑 0.0.0.0"的手段。

**⑫ 断言里不能藏环境前提 —— 包括"进程继承了什么环境变量"。**
两次真实踩坑：
- 第一次：断言要求响应含 `status`，而 `status` 是 Analyzer `/health` 原样透传的字段 ⇒ **Analyzer 一停就误报失败**。代码一行没坏，排查却从"是不是我改坏了"绕一圈。
- 第二次（更隐蔽）：测试沙箱里有个幽灵 Analyzer（`base_url` 写死 `127.0.0.1:1`）⇒ 恒定红。但**本机跑出来是全绿** —— 因为本机设了 `http_proxy`，`Popen` 不传 `env` 时子进程**继承代理变量**，`127.0.0.1:1` 被代理接管回 502 ⇒ 走了另一个错误分支。
**修法**：① 沙箱 `Popen` 显式剥离代理变量；② 断言按 `reachable` 分流而不是无条件要求。
**验收标准也改了**：这类脚本必须**带代理 + 无代理各跑一遍**才算绿。

**⑬ `subprocess` 不传 `env` 会继承本机代理，这是"假绿"的典型来源。**

### 4.4 油猴脚本（JS 侧）

**⑭ `Rules.load()` 返回的是包装对象 `{rules:[...]}`，喂给引擎前必须拆包。**
直接把包装对象传给 `evaluate_rule` ⇒ 它读 `rule.groups` 时拿到 `undefined` ⇒ 全部判 `needs` ⇒ **页面上一个角标都不出现**（只剩"已看完"，因为那是另一条路径）。这个 bug 真实踩过，四个调用点都中招。

**⑮ `getAllDerived()` 返回 Promise，同步代码当数组处理会得到空列表。**

**⑯ 油猴脚本必须诚实。** 三条红线：不依赖 Analyzer、不回写 B站、`raw` 层原样存不丢字段。数据窗口 ≈3 个月是结构性天花板，不靠"多滚几下"掩盖。

## 五、过程中的重要事实修正

| 原结论 | 修正 | 说明 |
| --- | --- | --- |
| 「2020–2025 的 `duration` 无法恢复」 | **推翻** | 漏查 Analyzer 侧原始 JSON；后又找到详情接口这条路 |
| 「点『⑥ 应用变更』会误标 435 条」 | **推翻** | `store.apply_rules()` **不写** `auto_skip` 列；真实风险来自 `/api/query` 的实时分类 |
| 「一条断言在 Analyzer 停止时失败 = 代码坏了」 | **推翻** | 是断言里藏了环境前提 |
| 「已加代码测过了 = 契约没问题」 | **推翻** | 假样本测不出键名漂移 |
