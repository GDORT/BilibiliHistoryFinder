```bash
python dev/userscript/build.py
```

⚠️ **不要加 `--check`** —— 它只校验旧产物、不重建（这个坑踩过）。

产物落**仓库根** `bili_history.user.js`。

### 3. 自查元数据头

产物前 14 行。当前状态（2026-10-11）：

**平台硬性要求对照：**

| 字段 | Greasy Fork | 脚本猫 | 本脚本 |
| --- | --- | --- | --- |
| `@name` | 必填 | 必填 | ✅ |
| `@namespace` | **必填，更新时不可改** | 必填 | ✅ 已固定为仓库 URL |
| `@version` | **必填，代码变了必须递增** | 必填 | ✅ 改了功能就升 |
| `@description` | 必填 | **须准确反映功能与影响** | ✅ 已含隐私声明 |
| `@match` | 至少一个 | 至少一个 | ✅ 两个 |
| `@license` | **不填会警告** | **不声明则版权归作者且不视为开源** | ✅ MIT |
| `@antifeature` | — | 有返佣/广告/付费/挖矿/追踪须标 | ✅ **无，无需标**（本地脚本无任何一项） |

⚠️ **`@namespace` 一旦发布就不能改** —— 它 ＋ `@name` 是脚本管理器判断"是否已安装"的唯一依据，改了会被当成另一个脚本。已固定为仓库 URL，不要动。

已实测确认（2026-10-11）：

| 检查项 | 结果 |
| --- | --- |
| 对外请求（外部 `fetch` / `GM_xmlhttpRequest` / beacon） | ✅ **零** |
| `document.cookie` / `SESSDATA` 读取 | ✅ **零** |

## 四、Greasy Fork 发布步骤

1. 注册并登录 https://greasyfork.org
2. 点「**Scripts → Post a new script**」（发布新脚本）。
3. 打开 `bili_history.user.js`，**全选复制**整份内容粘进代码框。
4. **Additional information** 区域：
   - **Description** → 粘 [`油猴脚本发布页.md`](油猴脚本发布页.md) 的正文（可精简，Greasy Fork 支持 Markdown）
   - **Categories** → 选 *Other* ＋（可选）*Others*；中文站可加 *Bilibili*
   - **License** → 选 **MIT**（对应 `@license`）
5. 点「Publish」。首次发布可能进**待审队列**，Greasy Fork 通常几小时到几天。
6. 过审后拿到脚本 ID（如 `12345`），把发布页里的安装链接占位符替换为：
   ```
   https://greasyfork.org/scripts/12345/code/bili_history.user.js
   ```

**更新已发布的脚本**：进脚本页 →「Edit」→ 改 `@version` → 粘新代码 → Publish。**`@version` 必须大于线上版本。**

⚠️ Greasy Fork 会**剥离** `@updateURL` / `@downloadURL` —— 从它装的脚本只从它更新。这是平台的既定行为，不必对抗。

## 五、脚本猫发布步骤

1. 注册并登录 https://scriptcat.org
2. 点「**发布脚本**」。
3. 同上：**整份粘贴** `bili_history.user.js` 内容。
4. 填标题、简介（粘发布页正文）。
5. 提交后进**人工审核**。脚本猫审核会看：代码是否可读、有无恶意行为、`@description` 是否如实、许可证是否声明。
6. 过审后拿到脚本 ID（如 `5678`），安装链接为：
   ```
   https://scriptcat.org/scripts/5678/code
   ```

**更新**：进脚本管理页 → 编辑 → 改 `@version` → 提交。

⚠️ 脚本猫审核规则里有几条对本项目**天然有利**：
- 不禁止**本地存储**类脚本（本脚本数据全在本机）
- 不要求脚本有 `@grant` 特权（我们正是 `none`）
- 明确"未声明 `@license` 不视为开源" —— 我们已声明 MIT

## 六、发布后的版本管理

**改代码 → 必须递增 `@version`**（两个平台都会在版本回退时警告，且脚本管理器靠它判断要不要更新）。

建议的版本语义：

| 变化 | 版本动作 |
| --- | --- |
| 修 bug / 小调整 | patch 位 +1（0.4.1 → 0.4.2） |
| 新功能 | minor 位 +1（0.4.1 → 0.5.0） |
| 改数据结构（影响导出 schema） | minor 位 +1 **并在发布页的 FAQ 里说明** |

改完 `header.js` 后**必须**跑 `python dev/userscript/build.py` 重建产物 —— 否则提交的是旧产物。
