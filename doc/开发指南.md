## 一、代码在哪、跑起来要什么

### 1.1 目录职责

```
BilibiliHistoryFinder/
├── src/            ← 运行时代码（纯 Python 标准库，零依赖零构建）
│   ├── server.py       HTTP 服务与全部端点（:8765）
│   ├── store.py        只读数据层：Analyzer 主源 + 本地库合并 → canonical
│   ├── engine.py       规则引擎（纯逻辑，无 I/O，可脱库单测）
│   ├── collector.py    采集器（仅 mode=local 时按需调用）
│   └── web/            前端单页（原生 HTML/CSS/JS）
├── data/           ← 运行态数据（已 gitignore）
├── dev/            ← 测试资产（src/ 不 import 任何东西）
├── doc/            ← 本文档区
├── userscript/     ← 独立入口 B：油猴脚本（自成一体，见其内说明.md）
├── config.json     ← ⚠️ 含 SESSDATA，已 gitignore；新环境需手动创建
├── start.bat / stop.bat
└── doc/BilibiliHistoryFetcher-master/  ← 第三方源码参考（已 gitignore，本机 clone）
```

### 1.2 跑起来

```bat
start.bat          :: 启动（顺带拉起 Analyzer；重复双击不会起第二个）
:: 浏览器打开 http://127.0.0.1:8765
stop.bat           :: 关闭（同时关掉 Analyzer；关窗不卡 pause）
```

依赖：**Python 3.8+**，标准库即可，不需要 pip 安装任何东西。

### 1.3 换机器 / 新机器部署（迁移清单）

`data/` 与 `config.json` **不在版本库里**（前者是个人观看历史，后者含真实 SESSDATA），换机器要手工搬。按下表复制即可：

| # | 做什么 | 说明 |
| --- | --- | --- |
| 1 | `git clone` 本仓库 | 代码 ＋ 文档 ＋ 测试 ＋ 油猴脚本全在里面 |
| 2 | `cp config.example.json config.json`，填自己的 `SESSDATA` | ⚠️ **键名是大写 `SESSDATA`**（写小写会读成 0，表现为"配了但没生效"） |
| 3 | **整个复制 `data/` 目录** | 库表、文件名全部可移植 —— `bilibili_history.db` 的 27 列**没有任何一列存路径**，可直接拷 |
| 4 | **改 Analyzer 安装目录**（见下） | 唯一需要动的一处 |
| 5 | 装 Analyzer（8899）＋ 配它自己的 SESSDATA | 在 `_internal/config/config.yaml`（⚠️ **不是** `config/` 目录） |
| 6 | `dev/e2e/setup.ps1` | 仅当要跑前端冒烟（A1）时需要 |
| 7 | `python dev/run_all.py` | 应全绿 |

`data/` 里各文件的可移植性（实测核对过表结构）：

| 文件 | 能否直接拷 | 依据 |
| --- | --- | --- |
| `bilibili_history.db`（4512 条） | ✅ | 27 列全是内容字段；`meta` 表只存同步游标，重跑同步自动刷新 |
| `canonical_state.db` | ✅ | `meta` 只有规则哈希；**6 条 `skip_state` 是你的分类状态，必须带走** |
| `rules.json` | ✅ | 纯规则定义，无路径 |
| `covers/` | ✅ | 文件名就是 `kid`，与机器无关；缺了下次浏览按需重下 |
| `backup/` | ✅ | 快照天然可移植 |
| `source_config.json` | ✅ | 见下 |

#### Analyzer 库路径怎么配（2026-10-11 改）

**配置里写相对路径，不要写绝对路径。**

```json
{ "mode": "auto", "analyzer_db": "output/bilibili_history.db" }
```

这一条相对 **Analyzer 的安装目录**解析 —— 因为 `output\bilibili_history.db` 是它**内部固定**的位置，真正因机器而异的只是安装目录那一段。换机器时只改安装目录，配置本身不用动。

三级优先级（高 → 低）：

| 优先级 | 来源 | 用途 |
| --- | --- | --- |
| 1 | 环境变量 **`ANALYZER_DB`** | 直接给完整库路径 —— 测试沙箱靠它锁幽灵路径 |
| 2 | 环境变量 **`ANALYZER_HOME`** | 只给安装目录，库路径由代码拼出 ← **换机器时用这个** |
| 3 | `store.py` 的 `_DEFAULT_ANALYZER_HOME` | 打包器默认安装位置 |

`store.resolve_analyzer_db()` 接受三种写法：绝对路径（原样，**兼容旧配置**）· `output/bilibili_history.db`（相对安装目录）· `bilibili_history.db`（只给文件名）。

⚠️ **为什么不能写绝对路径**：路径失效时 Finder **不报错**，而是静默降级成 `mode=local` —— 界面上只显示"用本地库"，看起来迁移成功了，实际 Analyzer 中继全部失效。

⚠️ 相对路径的基准**不是本项目根目录** —— 两者通常不在同一个父目录下（Analyzer 在 `C:\Program Files (x86)\`，本项目在别处），用项目根当基准会拼出根本不存在的路径。

## 二、要改代码时（四个最常见场景）

### 场景 1 · 改规则逻辑（`src/engine.py`）

改完**必须**跑：

```bat
python dev/test_engine.py        :: 114 项，纯逻辑，毫秒级
```

引擎的两个反直觉实现（漏掉就会语义偏离）：

- `eval_condition` 对 `duration` 的「有值才判」守卫 —— `None` 或 `<=0` 判 False，但**刻意不拦** `exists` / `empty`
- `apply_sort` 是**分段**排序（有值段按方向排 ＋ 缺值段永远末尾），**不是** `sort(reverse=True)`

### 场景 2 · 改后端端点 / 启动流程 / 配置读写

```bat
python dev/verify_riskfix.py     :: 97 项，整进程级黑盒验收
python dev/test_api_contract.py  :: 97 项，端点契约
```

`verify_riskfix.py` 会把 `src/` 整目录复制到临时目录再起真进程 —— 所以**它验的是"真实 `main()`"**，不是副本。

### 场景 3 · 改前端 DOM

```bat
python dev/run_all.py --with-a1  :: 含 A1 前端冒烟（G1–G6，54 项）
```

⚠️ **改了 `CAP_DOM`（前端能力表）必须同步 `dev/e2e/smoke_frontend.py` 的 `BASELINE_SELECTORS` 基线清单**，否则 A1 会红 —— 这是它防"假绿"的设计目的，不是误报。

同时注意能力表是**两维**的，混在一张表里必然出错：

| 维度 | 表 | 判据 | 回答 |
| --- | --- | --- | --- |
| 能力 | `CAP_DOM`（前端 JS） | `caps[cap].available` | 这件事能不能做 |
| 端点归属 | `ANALYZER_ONLY_DOM` | `connection.analyzer.ok`（**业务级**） | 这个按钮的端点在不在 Analyzer 上 |

### 场景 4 · 改数据抓取 / 同步策略

```bat
python dev/regression_fallback.py   :: 增量→全量回退的端点端到端
python dev/regression_restart.py     :: 重启链路
python dev/test_finder_collect.py    :: Finder 自身抓取（假 B站，零实网）
```

## 四、写新测试的硬规矩

这七条是踩出来的，**违反其中任何一条都会产生假绿**：

1. **拓扑必须与生产同构** —— 要测 HTTP handler 里的逻辑就真起 handler 发真请求，**别把那段 `if` 抄进脚本**
2. **优先内存覆盖而不是改磁盘配置** —— 少一个"必须还原"的步骤
3. **必须有反例对照** —— 永远返回 `true` 的实现也能通过正向测试
4. **副作用函数打桩，被测的分支判定保持真实**
5. **假样本测不出键名漂移** —— 凡"两侧约定"的结构（请求 ↔ 响应），必须有一条断言拿**真实产出**驱动消费方
6. **要测启动期行为就复制仓库跑真进程** —— 配 `netstat` 独立核对，别信被测代码自称
7. **断言里不能藏环境前提** —— 包括"服务在不在跑"和"进程继承了什么环境变量"

每条的原始事故见 [`开发历程回顾.md`](开发历程回顾.md) §4.3。

### 7.1 代码质量与结构技术债（2026-10-11 收尾评估）

> 收尾时对 `src/*.py` 做了一次风格审查，以下为**已知但暂缓**的改进点——功能可用、均不阻塞，待未来真正要改对应代码时一并收拾。

| 类别 | 位置 | 问题 |
| --- | --- | --- |
| 巨型路由 | `server.py` `do_GET`(≈248 行) / `do_POST`(≈463 行) | if/elif 路由链过长，未按资源拆 handler |
| 职责越界 | `server.py` `_backup_*` / `_count_db_records` | 编排层混入本属 `store.py` 的持久化细节 |

| 重复实现 | `server.py` `_write_json_file` ≅ `store.py` `_write_json_atomic` | 原子写 JSON 写了两遍 |
| 薄封装 | `server.py` 对 `engine.py` 的 `get_active_rule`/`validate_rule`/`rules_hash` 仅一行转发 | 语义重复、徒增跳转 |
| 历史注释 | `engine.py` `#41`/`#42` 注释块、`server.py`「审查稿/2026-10-01 修」式注释 | 改动史写进代码，长期引用会过时 |

| 性能 | `engine.py:_derived` 每次条件求值重算 | `classify` 里每条×每条件都触发；几千条无碍，可缓存 |
